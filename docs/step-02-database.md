# Шаг 2. Основа базы данных

На этом шаге мы не делаем Telegram-бота и не делаем интерфейс.

Сначала мы закладываем основу данных, потому что все приложение будет опираться именно на нее.

## Какие сущности есть в MVP

### 1. Пользователь

Таблица: `app_users`

Хранит Telegram-пользователя:

- `telegram_user_id`
- `username`
- `first_name`
- `last_name`

### 2. Валюты

Таблица: `currencies`

Хранит список валют:

- `USD`
- `EUR`
- `RUB`
- `GEL`

Позже можно будет легко добавлять другие валюты.

### 3. Курсы валют

Таблица: `exchange_rates`

Хранит курс одной валюты к другой.

Пример:

- `USD -> GEL`
- `EUR -> RUB`

Эта таблица нужна для:

- общего баланса
- конвертации
- отчетов в одной валюте

### 4. Счета

Таблица: `accounts`

У каждого счета есть:

- название
- тип счета
- валюта
- текущий баланс

Типы счета в MVP:

- `cash`
- `card`
- `crypto`
- `savings`
- `other`

### 5. Категории

Таблица: `categories`

Категории делятся на 2 вида:

- `income`
- `expense`

Примеры:

- доход: `salary`, `freelance`
- расход: `food`, `transport`, `rent`

### 6. Доходы и расходы

Таблица: `entries`

Эта таблица хранит обычные операции:

- доход
- расход

У записи есть:

- сумма
- валюта
- счет
- категория
- комментарий
- дата
- фото

### 7. Переводы

Таблица: `transfers`

Перевод вынесен в отдельную таблицу, потому что это удобнее и понятнее.

Например:

- со счета `USD card`
- на счет `GEL cash`

Здесь могут отличаться:

- сумма списания
- сумма зачисления
- валюта отправки
- валюта получения
- курс

## Почему переводы отдельно

Если хранить перевод как обычный расход или доход, потом будет путаница:

- отчеты станут сложнее
- можно случайно посчитать перевод как расход
- баланс может считаться неправильно

Поэтому для MVP проще и правильнее хранить переводы отдельно.

## Как в MVP будет обновляться баланс

На первом этапе баланс хранится прямо в таблице `accounts`.

То есть приложение будет делать так:

1. пользователь создает доход
2. приложение добавляет запись в `entries`
3. приложение увеличивает баланс нужного счета

Для расхода:

1. создается запись в `entries`
2. баланс счета уменьшается

Для перевода:

1. создается запись в `transfers`
2. уменьшается баланс исходного счета
3. увеличивается баланс целевого счета

Это не самая сложная схема, зато она очень понятная для MVP.
